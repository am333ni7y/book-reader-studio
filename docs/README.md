# Project Technical Documentation & Decision History

This directory documents the technical decisions, architecture, empirical evaluations, failure investigations, and milestone retrospectives behind this project, following the Universal Project Decision & Implementation Documentation Rule.

## Directory Structure

- **`decisions/`**: Architecture Decision Records (ADRs) tracking what was chosen, what was rejected, and why.
- **`failures/`**: Post-mortems, bug analyses, dead ends, and preventative lessons.
- **`architecture/`**: Component specifications, state flow invariants, and parameter derivations.
- **`milestones/`**: Syntheses answering the 16 core engineering questions at major project milestones.
- **`templates/`**: Standard markdown templates for new records.

## Core Mandates

1. **Document the Path**: Never document only the final answer; record the context, alternatives, and trade-offs.
2. **Empirical Grounding**: Clearly distinguish observed facts from interpretations and assumptions.
3. **No Retrospective Fabrication**: State whether reasoning is contemporaneous or reconstructed.
